# 代码审查清单

## 1. 功能完整性

- [ ] 代码实现了需求文档中的所有功能
- [ ] 所有用户故事和用例都已覆盖
- [ ] 边界条件和错误情况都有处理
- [ ] 必要的回调和事件处理都正确实现

## 2. 代码质量

### 2.1 可读性
- [ ] 代码命名清晰有意义（变量、函数、类名）
- [ ] 函数长度适中（不超过50行）
- [ ] 避免重复代码，提取公共函数
- [ ] 复杂的业务逻辑有注释说明

### 2.2 可维护性
- [ ] 模块间低耦合，高内聚
- [ ] 遵循单一职责原则
- [ ] 配置数据外部化
- [ ] 没有硬编码的值

### 2.3 代码风格
- [ ] 遵循项目编码规范
- [ ] 缩进和格式化一致
- [ ] 导入顺序正确
- [ ] 遵循Git提交规范

## 3. 错误处理

- [ ] 所有异步操作都有错误处理
- [ ] 错误信息清晰且对用户友好
- [ ] 敏感错误不暴露给客户端
- [ ] 错误日志记录完整
- [ ] 使用统一的错误处理机制

## 4. 安全性

- [ ] 用户输入经过验证和清理
- [ ] 防止SQL注入（使用参数化查询）
- [ ] 防止XSS攻击
- [ ] 敏感信息不硬编码
- [ ] 身份验证和授权正确实现
- [ ] 速率限制正确配置

## 5. 性能

- [ ] 数据库查询优化（有索引）
- [ ] 避免N+1查询问题
- [ ] 合理使用缓存
- [ ] 没有内存泄漏
- [ ] 大数据量处理使用分页

## 6. 测试

- [ ] 核心功能有单元测试
- [ ] 测试覆盖率达标
- [ ] 测试用例覆盖正常和异常流程
- [ ] 测试相互独立
- [ ] 测试名称清晰描述测试内容

## 7. API设计

- [ ] RESTful URL设计规范
- [ ] HTTP方法使用正确
- [ ] 响应格式一致
- [ ] 状态码使用正确
- [ ] 支持分页和过滤

## 8. 文档

- [ ] API接口有文档
- [ ] 复杂逻辑有注释
- [ ] README更新（如有必要）
- [ ] 数据库Schema有文档

## 审查级别定义

### 🔴 阻塞性问题（必须修复）
- 安全漏洞
- 数据丢失风险
- 系统崩溃风险
- 严重性能问题

### 🟡 重要问题（建议修复）
- 错误处理不完善
- 测试覆盖率不足
- 代码可读性差
- 重复代码

### 🟢 建议改进（可选）
- 代码风格不一致
- 注释可以更详细
- 小型性能优化

## 审查流程

1. **作者准备**
   - 确保代码通过所有自动化测试
   - 确保本地构建成功
   - 准备清晰的PR描述

2. **审查者检查**
   - 运行代码审查清单
   - 测试代码变更
   - 验证性能影响

3. **反馈和修复**
   - 提供具体的改进建议
   - 作者修复问题
   - 重新审查

4. **合并**
   - 所有阻塞性问题已修复
   - 至少一个审批通过
   - 分支测试通过
